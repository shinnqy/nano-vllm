# 从零实现 Nano-vLLM：从入口出发的逐步指南

这份指南带你在**一个空目录**里，亲手写出和本项目功能完全相同的 LLM 推理引擎。全程按有 GPU 的环境来写。

## 这份指南的写法：总 → 分

很多教程先讲零件，再组装。读的时候你不知道这个零件要用来干什么，只能硬记。

这份指南反过来：

1. **先写入口。** 第 2 章就从 `example.py` 写起，内部全用假实现，让整条链路先跑通。
2. **看症状。** 程序跑起来后，看它哪里不对、哪里慢、哪里会崩。
3. **由外往里改。** 每次只解决一个问题：先改最外层，发现里面缺什么，再进去写什么。

所以你写每一个类时，都清楚**它是被谁需要的，要解决什么问题**。

从第 2 章开始，`python example.py` 始终能运行，只是内部越来越真实。

## 怎么用这份指南

**按章节顺序写，不要跳。** 代码是逐章修改的，后面的修改依赖前面的结果。

每章都按同一个结构展开：

- **上一章留下的问题**：现在看到了什么症状。
- **由外往里改**：先改最外层，遇到缺的东西再往里走。
- **检查点**：用什么确认问题解决了，以及新的症状是什么。

**建议的工作方式：**

1. 读完症状和思路后，**先试着自己写**。
2. 写不出来再对照指南。
3. 过了检查点再往下。
4. 和本项目的同名文件对比。

代码块上方的说明会告诉你怎么改，比如“替换这个方法”“在这一行后面加入”。

## 每章固定回答的四个问题

| 问题 | 在哪里 |
|---|---|
| 这一步要解决什么？要实现什么？要调用什么？为什么这样做？ | 每章开头的**任务卡** |
| 这一行代码为什么这样写？ | 代码后面的**逐行看** |
| 跑起来数据长什么样？ | **走一遍**，用真实的数字把代码走一遍 |
| 这个 API 是干什么的？这个功能在哪一章？ | [附录 A：API 速查](appendix-a-api.md)、[附录 B：功能覆盖和调用链](appendix-b-coverage.md) |

第一遍可以只看任务卡和代码，把程序写出来。卡住的时候再看逐行讲解。写完之后，试着不看讲解，向别人解释每一行。

## 项目最终的样子

括号里是这个文件**第一次出现**的章节：

```text
my-vllm/
├── example.py                    (2) 入口，一切的起点
├── bench.py                      (10) 压测
├── tests/                        各章检查点（本项目没有，是这份指南额外加的）
└── nanovllm/
    ├── __init__.py               (2)
    ├── llm.py                    (2) 对外的类名
    ├── sampling_params.py        (2) 每个请求的采样参数
    ├── config.py                 (2) 引擎配置
    ├── engine/
    │   ├── llm_engine.py         (2) 主循环，串起下面三者
    │   ├── sequence.py           (2) 一个请求的全部状态
    │   ├── scheduler.py          (2) 这一轮算谁
    │   ├── model_runner.py       (2) 让 GPU 真正跑起来
    │   └── block_manager.py      (6) 物理块的账本
    ├── models/
    │   └── qwen3.py              (3) 模型结构
    ├── layers/
    │   ├── sampler.py            (3) 从 logits 采样
    │   ├── embed_head.py         (3) 词嵌入与输出头
    │   ├── layernorm.py          (3) RMSNorm
    │   ├── linear.py             (3) 合并投影
    │   ├── activation.py         (3) SiLU × 门控
    │   ├── attention.py          (4) KV 读写 + 注意力
    │   └── rotary_embedding.py   (4) 位置编码
    └── utils/
        ├── loader.py             (4) 加载权重
        └── context.py            (5) 每轮的隐藏参数
```

## 这份指南的验证情况

把所有章节的代码修改依次应用后，得到的最终代码已和本项目源码逐文件做过 AST 比对（忽略注释和定义顺序）。各章检查点的运行范围见[第 12 章末尾](12-troubleshooting-and-next-steps.md#指南本身的验证范围)。

**真实 GPU、Triton、FlashAttention 的部分，编写时没有条件实际运行**（编写所用的机器没有 GPU），需要你第一次在 GPU 机器上跑时自行确认。
